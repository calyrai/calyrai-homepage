System concept

3 SENSOR NODES -> NETWORK -> CENTRAL_NEXUS_SERVER -> SHARED_SCENE_NODE

Nexus.Engine is the orchestration layer that turns raw sensing into governed runtime states. The MVP should remain narrow: phone motion and capture signals go in, the browser shows live state out, and the server merges them into one world.

The LiDAR module now exists as a structural runtime scaffold in nexus/engines/lidar; this page is the user-facing system overview for that scaffold.

Runtime layers

1 Multi-phone capture LiDAR, motion, camera, touch, position, and button events are acquired on several devices in the same room.
2 Shared world alignment ARKit collaborative sessions or reference points keep devices in one coordinate system.
3 WebSocket / API bridge Transport relays the merged stream to the backend and keeps the UI decoupled from the devices.
4 Semantic projection Raw frames become capture states, geometry states, and interface states.
5 Web visualization React, SVG, or Three.js surfaces show the system and allow interaction.

MVP flow

The first useful prototype does not need perfect synchronization or full LiDAR processing. It only needs several phone streams, a backend relay, and a browser that reacts in real time.

iPhone 1 + iPhone 2 + iPhone 3 -> network -> central Nexus.Engine server -> shared scene

That is the interface you asked to see: the systems behind the MVP, not the device link implementation itself.
