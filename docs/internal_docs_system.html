Adding a page

  1. Create the .md file under docs/.
  2. Add an entry to mkdocs.yml: 
    nav:
  - My Section:
      - My Page: path/to/my_page.md
  3. Run mkdocs serve — hot-reloads automatically.

Serve / build

cd /path/to/Calyr
mkdocs serve          # → http://localhost:8000
mkdocs build          # → build/docs_site/

Known build issue

mkdocs build --strict fails on broken docs/_repo/ symlinks auto-generated by tools/repo/build_docs_hub.py where the targets no longer exist (e.g. _repo/apps/homepage/pages_src/). Non-strict builds and mkdocs serve are unaffected. Regenerate with: 

python3 tools/repo/build_docs_hub.py

UI sections on topic_planner.html

SectionPurpose
Topic create rowAdd new topics dynamically.
Topic cardsPer-topic circle controls for work and meaning.
Planner actionsGenerate plan, export topic_plan.json, copy sync command.
Day plan panelShows generated assignments for MO–SU.
Calendar sync noteOperator command to push plan into Google Calendar.

Scheduling logic contract

  • Each topic has two values: work (effort) and meaning (importance).
  • Planner score is weighted to keep semantic priority dominant.
  • Output is a topic_plan JSON object with weekday_labels, daily_block, and review_block.
  • Google Calendar sync accepts this JSON directly via --topic-plan-json.

Command path (UI export → Calendar sync)

# 1) Export topic_plan.json from the planner UI
# 2) Validate without writing to Google
python administration/google_calendar_sync.py \
  --config administration/google_calendar_config.json \
  --sync-topic-plan \
  --topic-plan-json /path/to/topic_plan.json \
  --dry-run

# 3) Write recurring events to Google Calendar
python administration/google_calendar_sync.py \
  --config administration/google_calendar_config.json \
  --sync-topic-plan \
  --topic-plan-json /path/to/topic_plan.json

calyr.vox layout (internal synthetic voice-over surface)

A dedicated internal voice system now exists to turn slide snippets into narrated outputs: slides -> speaker text -> TTS audio -> timing -> video export. It is available both as a Python pipeline and as a one-file browser studio. 

apps/homepage/vox.html                       ← login-gated internal entrypoint (homepage surface)
apps/homepage/js/vox_gate.js                ← auth/session gate for Vox page
apps/homepage/pages/vox_studio.html         ← embedded studio content served from homepage path

apps/vox/vox_studio.html                     ← canonical standalone studio source
apps/vox/calyr_vox.py                        ← CLI orchestrator (speak, synth, video, all)
apps/vox/speech_generator.py                 ← LLM speech generation (natural narration)
apps/vox/tts_engine.py                       ← TTS dispatcher (OpenAI + ElevenLabs)
apps/vox/timing_engine.py                    ← duration estimation + ffprobe timing
apps/vox/video_exporter.py                   ← ffmpeg segment render + concat
apps/vox/README.md                           ← operational usage contract

calyrai_modelling/snippets/slides/*.yaml     ← slide snippet inputs
output/vox/                                  ← voiced yaml + audio + manifest + final mp4

Voice systems (both supported)

SystemUse caseRequired keysNotes
Generic voice (OpenAI TTS) Fast default narration for immediate production runs. OPENAI_API_KEY Stable quality, no cloning required, selectable stock voices.
Cloned voice (ElevenLabs) Personalized delivery where speaker identity should match your own voice. ELEVENLABS_API_KEY + voice_id Requires recording upload first; then use returned voice_id for synthesis.

HTML studio tabs and responsibilities

Access mode (internal/login)

  • Public homepage links should point to vox.html, not directly to the raw studio file.
  • vox.html shows an auth gate and reveals the studio only after login token/session is present.
  • Login handoff follows the same token/session pattern as Citizen (?token=...&user=... or existing local session).

Slide snippet contract for calyr.vox

id: slide_legacy_reporting_001
type: slide
title: Legacy Reporting System
bullets:
  - Oracle Warehouse Builder
  - SAP BusinessObjects
  - 20 years legacy
tone: professional
duration: 30s

Speech generation rules (internal contract)

  • Do not read bullet points verbatim; synthesize into natural narration.
  • Respect tone (for example professional, scientific, casual, motivational).
  • Honor duration guidance; default timing model assumes ~150 words per minute.
  • Write speaker text back to voiced YAML for reproducible regeneration.

Voice cloning operator path (ElevenLabs)

# 1) Record or upload clean speech sample in the studio
# 2) Create clone via ElevenLabs endpoint
POST https://api.elevenlabs.io/v1/voices/add

# 3) Persist returned voice_id
ELEVENLABS_VOICE_ID=<your_voice_id>

# 4) Synthesize with cloned voice
python apps/vox/calyr_vox.py all calyrai_modelling/snippets/slides/ \
  --provider elevenlabs \
  --voice $ELEVENLABS_VOICE_ID \
  --out output/vox

CLI path (batch generation)

# Full run: slides -> speech -> audio -> video
python apps/vox/calyr_vox.py all calyrai_modelling/snippets/slides/ --out output/vox

# Speech only (no TTS/video)
python apps/vox/calyr_vox.py all calyrai_modelling/snippets/slides/ --dry-run

# Stepwise mode
python apps/vox/calyr_vox.py speak calyrai_modelling/snippets/slides/slide_legacy_reporting_001.yaml
python apps/vox/calyr_vox.py synth output/vox/voiced/slide_legacy_reporting_001.yaml --provider openai
python apps/vox/calyr_vox.py video output/vox/manifest.json

Security and storage notes

  • The browser studio stores API keys in local browser storage for internal convenience; do not use shared browser profiles.
  • For production operators, prefer environment variables and CLI execution in a controlled shell.
  • Do not commit API keys, raw samples, or generated tokens into repository history.

Adding a page

  1. Create apps/homepage/docs/<section>_<page>.html: 
    <article class="doc-article">
  <h1>Page Title</h1>
  <p class="doc-subtitle">One-liner</p>
  <h2>Section</h2>
  <p>Content</p>
</article>
  2. Register it in apps/homepage/data/docs.js: 
    { id: 'my_page', title: 'My Page', src: 'docs/section_my_page.html' }
  3. Live immediately at docs.html#section/my_page — no build step.

Naming convention

docs/<section_id>_<page_id>.html — matches the id fields in docs.js.

Content addressing standard (structure-first)

For publication surfaces and long-lived content, prefer structure-driven paths over concatenated file names like name_name2_.html. Paths should express meaning and hierarchy. 

content/
  papers/
    saxs-unified/
      index.html
  slides/
    okto-intro/
      index.html
  concepts/
    pdd-duality/
      index.html

Rule: each page lives in its own directory with an index.html entrypoint. Use lowercase, hyphen-separated slugs (for example saxs-unified, okto-intro).

Object identity for Okto

Store an explicit object identity alongside each content page:

id: paper_saxs_unified
slug: saxs-unified
type: paper

Routing can then be generated deterministically via: content/{type}/{slug}/index.html.

Migration strategy

  1. Map legacy names (name_name2_.html) to semantic slugs (saxs-unified).
  2. Move into structured folders (for example content/papers/saxs-unified/index.html).
  3. Add optional redirect pages for legacy links where external references exist.
  4. Mirror the same structure under archive/ for clean historical retention.
